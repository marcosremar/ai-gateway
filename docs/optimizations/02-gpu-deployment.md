# GPU Providers & Deployment — 100 Optimizations (IDs 101-200)

> This audit covers the GPU deployment orchestration domain: provider cascade (RunPod→Vast→TensorDock→Modal), race/hedged deploy with loser cancellation, VRAM validation, cost estimation, balance preflight, auto-select-cheapest, deploy lock/idempotency, per-deploy cost cap, pod lifecycle (stop/resume/terminate), SnapGPU/CRIU snapshots, SSH tunnels, and tier ranking. The single largest theme is **cost (economia)**: the documented "15-min idle auto-stop" is contradicted by a 4-hour adaptive idle floor (`MIN_IDLE_TIMEOUT_MS`), `maxCostUsd` is parsed but never enforced at runtime, race-deploy losers bill with no cost cap, and snapshot reuse is throttled by an OOM-prone in-memory base64 transfer. Reliability issues cluster around orphan/billing leaks (sequential teardown, `{apiKey}`-only cleanup that drops TensorDock `authId`, state reset before deletes confirm). Heavy code duplication (`src/gpu-providers/` ↔ `src/gateway/providers/gpu/` ↔ `src/modules/gpu-providers/`, plus two `validateVramForModel`/`GPU_VRAM_GB` copies and three handler trees) is a standing drift hazard. Several useful safety nets (`checkDeployWarnings`, `getGpuFallbacks`, `noTierCascade`) are dead code never wired into the deploy path. Line numbers are approximate and may drift by a few lines.
