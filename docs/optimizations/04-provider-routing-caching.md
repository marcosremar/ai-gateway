# AI Provider Integrations, Routing & Caching — 100 Optimizations (IDs 301-400)

> This audit covers the canonical provider/routing/caching code under `src/gateway/providers/cloud/`, `src/gateway/proxy/`, `src/gateway/routing/`, `src/caching*`, `src/lazy-provider/`, and `server/providers.ts` / `server/provider-warmup.ts` (the top-level `src/providers/*`, `src/proxy/*` files are thin re-export shims to `src/gateway/...`). The single highest-leverage theme is **cost (economia)**: the OpenAI-compatible proxy never does cross-provider fallback for STT/TTS/embeddings/images, has no TTS/image caching, drops every output-affecting LLM param (`tools`/`top_p`/`seed`/`stop`/`n`) so callers silently lose features, and none of the built intelligence modules (circuit breaker, performance ranker, adaptive timeout, TTFAC, token-cost-aware ranking) are wired into the proxy path. The streaming chat path is the worst offender — no fallback, no cooldown, no caching, no coalescing. A second cross-cutting issue is the ~80k-LOC `src/modules/` mirror that has already silently drifted from `src/` (e.g. `response-cache.ts`, `percentage-routing.ts`), so bug fixes land in only one copy. Findings are grounded in real code with file:line references; Cost is heavily represented per the brief.
