# Core AI Pipeline (STT → LLM → TTS) — 100 Optimizations (IDs 1-100)

> The core pipeline is well-architected: a pure orchestrator (`src/gateway/pipeline/pipeline-orchestrator.ts`) is wired to server state via DI (`server/pipeline-runner.ts`), racing/cancel-losers is centralized in `provider-racer.ts`, and there are real caches (translation LRU, speculative, voice-ref) plus hallucination filtering, ensemble STT, dub fanout and LLM→TTS streaming overlap. The biggest themes for improvement: (1) **Reliability** — a latent head-start race bug that drops fallbacks when the primary fast-fails, no AbortSignal propagation in `ensemble-stt.ts` (losers keep billing), and several swallowed/duplicated-failure paths; (2) **Cost** — `adaptiveMaxTokens` is computed but ignored on the hot streaming path (hard-coded `maxTokens: 200`), races fire 3-4 paid candidates without short-circuiting on a cached/free winner, no audio-duration guard before paying STT, and dub fanout re-pays LLM/TTS for concurrent duplicate targets; (3) **Functionality** — STT rolling-context/glossary are dropped on the streaming path, no per-segment hallucination filtering in the live pipeline, speculative cache never `speculate()`s from the SSE handler; (4) a serious **drift** issue: `src/modules/` is a stale mirror where `translation-cache.ts` still has the old LRU-promote-then-TTL bug and missing `.unref()`. Cost is heavily represented because every race multiplies paid upstream calls.

## Racing, hedging & cancel-losers
