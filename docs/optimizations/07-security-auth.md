# Security, Auth & Input Validation — 100 Optimizations (IDs 601-700)

> This audit covers the auth, vault, input-validation, SSRF, guardrail/DLP, and rate-limiting surfaces of AI Gateway. The security primitives themselves are mostly well-built (timing-safe compares with padding, explicit GPU-token claim validation, AES-256-GCM with auth tags, a thorough SSRF normalizer). The biggest systemic risks are **drift and dead code**: a near-complete `src/modules/` mirror duplicates the auth/SSRF/vault logic so fixes must land twice; several hardened modules (`requireRole`/RBAC, `csrfMiddleware`, `createPerKeyRateLimiter`, Cloudflare-style `detectPII`/DLP, `detectInjection`/`sanitizePrompt`, and the entire `handleRecallWebhook`) are **defined but never wired into the live server**, so the protection they document does not actually run. The second cluster is **cost-abuse exposure**: `ChatMessageSchema.content`/`messages` and `max_tokens` are unbounded, no global request quota exists, and DLP/guardrails ship disabled-by-default. The third is **localhost-exemption and fail-open foot-guns** across HTTP, WS, and Recall ingress when secrets are unset. Items below are grounded in specific files/lines; all are defensive hardening only.
