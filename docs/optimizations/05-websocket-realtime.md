# WebSocket, Streaming & Real-time Transport — 100 Optimizations (IDs 401-500)

> This audit covers the Bun-native WebSocket + SSE transport layer of the AI Gateway: `server/ws-server.ts` (single `Bun.serve()` upgrade + message router), `server/ws-state.ts` (broadcast/dub-subscription registry + binary frame packing), `server/ws/*` (speech, STT, bot-audio lifecycles), the HTTP/SSE adapter (`server/ws/http-api-server.ts`, `server/ai-handlers-stream.ts`), the upstream STT transport (`src/streaming-stt.ts`), streaming primitives (`src/streaming/index.ts`), webhooks (`src/webhooks/index.ts`), and the meeting-bot/recall/relay/video/avatar/lightning handlers. The most impactful systemic findings: (1) broadcast fan-out re-serializes per-connection and ignores Bun's native pub/sub and backpressure (`closeOnBackpressureLimit` is set but `getBufferedAmount` is never read), so a slow subscriber can stall the whole event loop or silently drop audio; (2) `handleChatCompletions` ignores `stream:true`, so OpenAI-compatible SSE clients hang; (3) the documented `/v1/speech/stream` SSE handler (`handlePipelineSSE`) is exported but never registered — dead/unreachable; (4) `src/` and `src/modules/` have drifted (the live library path `src/modules/webhooks/index.ts` is **missing the SSRF guard** present in `src/webhooks/index.ts`); (5) no server-initiated heartbeat and several process-lifetime timers never `unref()`/clear; (6) the single global `botAudioSource`/bot-audio buffer is process-global, so a second `/ws/bot-audio` connection clobbers the first and cross-talks all sessions. Items are spread across Functionality, Usability, Reliability, and Cost.
