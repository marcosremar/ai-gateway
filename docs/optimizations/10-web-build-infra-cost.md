# Web UI, Image Builder, Build & Infra/Cost — 100 Optimizations (IDs 901-1000)

> A code-grounded audit of the Next.js admin UI (`web/`), the GHCR image builder (`src/compute/image-builder/`), the tsup/turbo build tooling, the GPU/CUDA Dockerfiles, and the CI / Helm / Terraform / Fly / monitoring / load-testing infra. The single largest finding is the `src/modules/` tree: ~80k LOC of real (non-barrel) duplicated source mirroring top-level `src/`, which doubles type-check, lint, mutation, and build surface area for zero runtime value. The web layer pays repeatedly for (a) every section opening its own polling interval and a duplicate WebSocket with no `document.hidden` gating, (b) dozens of bespoke Card/badge/tile re-implementations of the shared `web/src/components/ui/` primitives, and (c) heavy client deps (`@xyflow/react`, `sortablejs`, two ~600-1800 LOC flow-diagram components) shipped even though only one diagram is used. CI re-installs deps without a Bun cache in ~12 jobs, builds the bundle 3× in the bundle/perf jobs, rebuilds all 3 Dockerfiles on any Dockerfile change, and never type-checks or builds `web/` at all. The GPU `babelcast-subtitle` image violates the project's own pre-bake + hf-xet guidance (models lazy-download at runtime, `hf_xet` never installed), and Helm/Fly/Terraform carry unpinned `:latest` images and over-sized default requests. Items are spread across Functionality, Usability, Reliability, and Cost, with Cost heavily represented per the brief.
