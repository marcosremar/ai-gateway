# AI Gateway — 1000 Optimizations Report

> A system-wide audit of the AI Gateway codebase identifying **1000 concrete, grounded
> optimizations** to make the platform **more functional for AI solutions, easier to use,
> less error-prone, and cheaper to run** (_mais funcional, mais fácil de usar, com menos
> erros, e com economia_).
>
> Generated by a fan-out of **10 specialized analysis agents**, one per domain, each
> grounding every finding in real source files (`file:line`). Detailed tables live in
> [`docs/optimizations/`](./optimizations/); this document is the executive index.

---

## 1. How to read this report

Every optimization is tagged along four axes so you can triage by value and cost-to-fix:

| Axis | Values | Meaning |
|------|--------|---------|
| **Lens** | `Functionality` · `Usability` · `Reliability` · `Cost` | Which goal the change serves |
| **Impact** | `High` · `Med` · `Low` | Expected benefit if implemented |
| **Effort** | `S` · `M` · `L` | Implementation size (Small <½ day, Medium ≤2 days, Large >2 days) |
| **Location** | `path:line` | Where the issue lives |

**The four lenses, defined for this codebase:**

- **Functionality** — make the platform more capable/correct for real AI workloads
  (better STT/LLM/TTS quality, more providers, richer routing, correct streaming).
- **Usability** — easier to adopt and operate (SDK/CLI ergonomics, secure defaults,
  config discovery, errors that guide the user to a fix, clear dashboards).
- **Reliability** — fewer bugs and outages (races, leaks, missing timeouts/retries,
  circuit-breaker correctness, data integrity, error handling).
- **Cost** — _economia_: cut GPU/cloud/token spend and waste (idle reaping, spot
  instances, cheapest-offer selection, caching/coalescing, smaller images & bundles,
  budget enforcement, anti-abuse).

> **Prioritization rule of thumb:** start with `High`-impact + `S`/`M`-effort items,
> and treat every `Cost` + `High` item as a candidate for the next sprint — those pay
> for themselves.

| Empty `catch {}` blocks | 12 | silent error swallowing |

### 🔴 Headline finding — duplicate library tree

`src/modules/` is a **near-complete mirror** of the top-level `src/` directory:
~90 of the same files/folders appear in both (`adapters`, `autoscaler`, `providers`,
`gateway`, `caching`, `auth`, `vault`, …), totaling **~80,000 duplicated lines**.
This is the single highest-leverage structural problem in the codebase:

- **Maintenance:** every fix must be applied twice or silently drifts.
- **Reliability:** two copies of auth, circuit-breaker, and cost logic _will_ diverge.
- **Cost:** shipping/bundling duplicate code inflates build time and artifact size.
- **Onboarding:** new contributors cannot tell which copy is authoritative.

Resolving this (collapse to one canonical tree behind the 12 published entry points)
is recommended as **Optimization #0 / prerequisite** and is referenced by many
per-domain findings below.
